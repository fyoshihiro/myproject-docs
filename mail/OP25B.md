# OP25B（Outbound Port 25 Blocking）
 
OP25B（Outbound Port 25 Blocking）は、スパムメールやウイルスメールの送信を防ぐために、ISPやクラウド事業者が外部のSMTPサーバーへの25番ポート通信を制限する仕組みです。
 
利用者が直接外部メールサーバーの25番ポートへ接続することを防ぎ、認証付きのメール送信（587番ポートや465番ポート）へ誘導することで、不正なメール送信を抑制します。

## OP25Bとは
 
OP25Bは「Outbound Port 25 Blocking」の略称で、日本語では「アウトバウンドポート25ブロッキング」や「メール送信規制」と呼ばれます。
 
SMTPの標準ポートである25番ポートへの外向き通信を遮断し、正規のメールサーバー以外からのメール送信を防止します。
 
### 通信イメージ
 
```text
利用者PC
│
│ SMTP(25)
▼
[ ISP ]
│
├─ × 外部SMTPサーバー（25番ポート）
│
└─ ○ ISP指定メールサーバー
│
└─ インターネット
```
 
---
 
## なぜ必要なのか
 
SMTPはもともと認証機能を持たない仕組みであり、過去にはウイルス感染したPCやスパム送信業者が25番ポートを利用して大量の迷惑メールを送信していました。
 
その結果、以下のような問題が発生しました。
 
- ISPのIPアドレスがブラックリスト登録される
- 正規ユーザーのメール配信にも悪影響が出る
- フィッシングメールや迷惑メールが増加する
 
これらを防ぐため、多くのISPやクラウド事業者でOP25Bが導入されています。
 
---
 
## OP25Bによる影響
 
OP25Bが有効な環境では、以下のような送信が制限されます。
 
### 送信できる
 
- ISPが提供するメールサーバーを利用した送信
- SMTP AUTHを利用した587番ポートでの送信
- SMTPS（465番ポート）での送信
 
### 送信できない
 
- 自前のメールサーバーから外部への直接送信
- 他社メールサーバーへの25番ポート接続
- ホテルや公衆Wi-Fiからの直接SMTP送信
 
---
 
## 回避方法
 
### 587番ポート（Submission）の利用
 
現在もっとも一般的な方法です。
 
SMTP AUTHによる認証が必須となります。
 
```text
SMTPサーバー : mail.example.com
ポート番号 : 587
暗号化 : STARTTLS
認証 : SMTP AUTH
```
 
### 465番ポート（SMTPS）の利用
 
SSL/TLSによる暗号化通信を利用します。
 
```text
SMTPサーバー : mail.example.com
ポート番号 : 465
暗号化 : SSL/TLS
認証 : SMTP AUTH
```
 
### メールリレーサービスの利用
 
業務システムやクラウド環境では、以下のようなメールリレーサービスを利用する方法があります。
 
- Microsoft 365
- SendGrid
- Amazon SES
- Google Workspace SMTP Relay

## 関連技術
 
### SMTP AUTH
 
利用者認証を行う仕組みです。
 
```text
ユーザー名 + パスワード
```
 
による認証を実施してからメール送信を許可します。
 
### SPF / DKIM / DMARC
 
OP25Bは「送信経路の制御」、SPF・DKIM・DMARCは「送信者の正当性確認」を行う仕組みです。
 
併用することで、より高いメールセキュリティを実現できます。
 
| 技術 | 目的 |
|--------|--------|
| OP25B | 不正な送信経路を遮断 |
| SPF | 送信元サーバー認証 |
| DKIM | 電子署名による改ざん防止 |
| DMARC | SPF/DKIM結果に基づくポリシー制御 |
 
---
 
## 運用のポイント
 
- メールクライアントは587番ポート＋SMTP AUTHを推奨
- 業務システムや複合機のメール送信設定も確認する
- SPF・DKIM・DMARCを併用する
- クラウド環境では25番ポートが制限されている場合が多いため注意する
- メール送信エラーが発生した場合は、まずOP25Bの影響を確認する

> **補足**
>
> OP25Bは「メールをどこから送るか」を制御する技術です。
>
> SPF・DKIM・DMARCは「そのメールが正当な送信者か」を認証する技術です。
>
> 現在のメールセキュリティでは、OP25B・SMTP AUTH・SPF・DKIM・DMARCを組み合わせて運用することが一般的です。
