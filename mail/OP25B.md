# OP25B(Outbound Port 25 Blocking)

OP25Bは、スパムメールやウイルスメールの送信を防ぐために、ISPやクラウド事業者が外部のSMTPサーバーへの25番ポート通信を制限する仕組みです。利用者が直接外部メールサーバーの25番ポートへ接続することを防ぎ、認証付きのメール送信(587番・465番ポート)へ誘導することで、不正なメール送信を抑制します。

## OP25Bとは

OP25Bは「Outbound Port 25 Blocking」の略称で、日本語では「アウトバウンドポート25ブロッキング」「メール送信規制」とも呼ばれます。SMTPの標準ポートである25番への外向き通信を遮断し、正規のメールサーバー以外からのメール送信を防止します。

### 通信イメージ

```text
① 利用者PC
     │
     ▼
② ISP(送信経路をチェック)
     │
     ├─ 25番ポート(直接送信)
     │    → × ブロックされる
     │
     └─ 587/465番ポート(認証あり)
          → ○ 許可される
               │
               ▼
          ③ インターネットへ到達
```

---

## なぜ必要なのか

SMTPはもともと認証機能を持たない仕組みであり、過去にはウイルス感染したPCやスパム送信業者が25番ポートを利用して大量の迷惑メールを送信していました。

| 問題 | 内容 |
|---|---|
| ブラックリスト登録 | ISPのIPアドレスが送信元として登録され、正規ユーザーにも影響 |
| 配信品質低下 | 正規メールまで届きにくくなる |
| フィッシング増加 | なりすましメールの温床になる |

これらを防ぐため、多くのISP・クラウド事業者でOP25Bが導入されています。

---

## OP25Bによる影響

| 送信できる | 送信できない |
|---|---|
| ISP提供のメールサーバー経由 | 自前メールサーバーからの直接送信 |
| SMTP AUTH + 587番ポート | 他社メールサーバーへの25番ポート接続 |
| SMTPS(465番ポート) | ホテル・公衆Wi-Fiからの直接SMTP送信 |

## 回避方法(正規の送信方法)

### 587番ポート(Submission)

現在もっとも一般的な方法。SMTP AUTHによる認証が必須です。

```text
SMTPサーバー : mail.example.com
ポート番号   : 587
暗号化       : STARTTLS
認証         : SMTP AUTH
```

### 465番ポート(SMTPS)

SSL/TLSによる暗号化通信を利用します。

```text
SMTPサーバー : mail.example.com
ポート番号   : 465
暗号化       : SSL/TLS
認証         : SMTP AUTH
```

### メールリレーサービスの利用

業務システムやクラウド環境では、以下のようなメールリレーサービス経由が確実です。

| サービス | 備考 |
|---|---|
| Microsoft 365 | Exchange Online経由でリレー |
| SendGrid | API/SMTPどちらも対応 |
| Amazon SES | AWS環境との親和性が高い |
| Google Workspace SMTP Relay | Gmail/Workspace利用者向け |

## 関連技術との違い

OP25Bは「送信経路の制御」、SPF・DKIM・DMARCは「送信者の正当性確認」を行う仕組みです。役割が異なるため、併用して初めて効果を発揮します。

| 技術 | 役割 |
|---|---|
| OP25B | 不正な送信経路(25番ポート直接送信)を遮断 |
| SMTP AUTH | 送信時のユーザー認証 |
| SPF | 送信元サーバーの正当性を認証 |
| DKIM | 電子署名による改ざん防止 |
| DMARC | SPF/DKIM結果に基づくポリシー制御 |

> 関連技術の詳細は [SPF / DKIM / DMARC](SPF.md) を参照してください。

## Tips

- **メールクライアント設定**: 587番ポート + SMTP AUTHをまず疑う。25番ポート指定のままだと送信エラーになりやすい。
- **複合機・業務システム**: 古い機器はデフォルトで25番ポート送信のことが多いため、設定変更が漏れやすい要注意ポイント。
- **クラウド環境(EC2/VPS等)**: 多くのクラウド事業者はデフォルトで25番ポートをブロックしている。送信できない場合はまずここを疑う。
- **送信エラー時の切り分け順**: ①ポート番号(587/465か) → ②認証情報 → ③SPF/DKIM/DMARCの設定、の順に確認すると原因特定が早い。
- **段階的移行**: 既存システムを587番に移行する際は、テスト送信で認証エラーが出ないか事前確認してから本番切り替えする。
